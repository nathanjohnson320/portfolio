### We're outta here
 
Officially leaving my job at STORD after 5 years. Feels a little strange and uneasy but also somewhat relieved. My contract stated that I needed to give 30 days notice and I'm stuck here for a while. There'll be a longer post at some point about that place, but for now I want to talk about drinking the koolaid for the last month I'm here.

We are essentially all in on AI going forward. That means E2E AI, the robots write the code, they review the code, then usually approve and then you control the shipping to prod. There are efforts underway to fully automate the engineer pipeline by a team that doesn't really work on the actual product we are building, mostly random CF garbage, not the elixir core. Testing it out I found a ton of issues with it and that got me thinking what would it look like if I completely phoned it in and built out a system to automate my incredibly boring last month at this job.

### Spin it up

I wanted to build something with selm and this app was a good first candidate. There's a lot of mcp/acp/port functionality baked into the language itself and that made it really easy to spin up. My first step has always been some level of high level planning. To start, I had to think about what I really do day to day. At this point it really isn't all that much.

1. I go to github and look for PRs to review
2. I go to our ticket system and pull new tickets to work if there's nothing to review
3. I monitor our email/log platform/chat platform for questions or issues

That's basically my job. Outside of that I really don't do anything else. Granted there can be big buckets of work inside of those like #2 especially, but mostly it's not that much.

So with that I went down the thought process of how can I turn this into an LLM powered slop fest and make my day job a point and click inbox of random tasks to delegate to agents.

The design I ended up with is like this, I'll have an inbox page that is based on a poll of ticket and github review assignments, and agent view for the currently processing agents, a flows tab which is like a high level diagram of what an agent should do based on a current direction, and then a general settings page.

By default selm gives you all the tools to do this stuff. You get the database (here I'm using sqlite for local), migrations, realtime with websockets (channels), port support on the BE (like actual external shells), mcp, acp, and lots more.

First thing I made was the inbox. That's where github notifications come in and PRs can be searched. This happens by directly sending messages to the gh CLI via a port.

![port](/img/articles/2026-11-18-kool-aid/inbox.png)

After this I added the Agents View. That's all the random agents I have running either cursor, claude, or my local LLM. My mac studio is pretty beefy so it can do some level of local stuff especially basics like handling ticket descriptions and classification. It looks like this:

![agent](/img/articles/2026-11-18-kool-aid/agent.png)

Then lastly the thing I needed was a way to direct the agent based on different conditions. This could be done in a single agent with a prompt but I wanted to leverage my local LLM stuff and avoid garbage token usage. Like a check if there are reviewers on the PR and flaky CI tests or failures shouldn't require a big boy agent to work. So to do that I built this UI workflow manager. You basically add steps and each step is evaluated when an agent reaches a done state. After the step it evaluates the conditions to see where to move next. I only really do two things with my day and that's why there's only two flows. Kind of sad, but oh well.

### Welcome to the software factory, the Koolaid tastes like diesel fuel

Now we've officially automated my job. I sit here and the agent does everything (lmao not really). There's still a lot of issues with this setup like the agents hallucinate and produce the wrong format between flow steps, and I don't really trust them end to end yet by giving them full control of everything so I'm still in the middle clicking buttons every now and again. But I can see this turning my job into a completely obsolete and unfulfilling profession.

Sad times.
